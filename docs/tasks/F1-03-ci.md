# F1-03 · CI en GitHub Actions (fase 1, corte 3)

Brief para Codex. Límites de entorno: los de `docs/tasks/F1-01-scaffold.md`. Objetivo: que cada push a `master` y cada PR ejecuten typecheck, lint, tests unitarios, pgTAP (`supabase test db`) y build. Sin Docker en local, este CI es el único sitio donde corre pgTAP: hasta que esté en verde, ninguna migración se da por válida.

## Entregable: `.github/workflows/ci.yml`
```yaml
name: ci
on: { push: { branches: [master] }, pull_request: {} }
concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with: { node-version-file: .nvmrc, cache: npm }
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm test
  db:
    needs: check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with: { node-version-file: .nvmrc, cache: npm }
      - run: npm ci
      - uses: supabase/setup-cli@v3
        with: { version: latest }
      - run: supabase start
      # nombres verificados con `supabase status -o env` (2026-10-30): API_URL, PUBLISHABLE_KEY, SECRET_KEY
      - run: |
          supabase status -o env | sed 's/"//g' > .sb.env
          . ./.sb.env
          echo "NEXT_PUBLIC_SUPABASE_URL=$API_URL" >> "$GITHUB_ENV"
          echo "NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=$PUBLISHABLE_KEY" >> "$GITHUB_ENV"
          echo "SUPABASE_SECRET_KEY=$SECRET_KEY" >> "$GITHUB_ENV"
      - run: npm run test:db
      - run: npm run build
```
- Comprueba las versiones vigentes de `actions/checkout`, `actions/setup-node` y `supabase/setup-cli` (`npm.cmd view` no sirve: mira sus repos con `gh.exe api repos/<owner>/<repo>/releases/latest --jq .tag_name` si `gh.exe` está disponible desde el sandbox; si no, deja las de arriba y dilo).
- Si `supabase status -o env` en la CLI 3.x cambió los nombres de variables, no lo sabrás desde local: deja un comentario en el YAML con la orden para comprobarlo y Claude Code lo revisará en el primer run.
- Los pasos de Playwright y Lighthouse **no** van todavía: llegan en el corte de auth (F1-04) cuando existan tests E2E; `playwright test` sin tests falla.
